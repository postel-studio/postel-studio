# S2 · 连接状态可见且可重连

- **里程碑** M1 · **预计** 3h · **依赖** S1 · **优先级** P0
- **用户路径**：页面右上角有状态灯 → 杀掉内核 → 灯变红并提示 → 重启内核 → 点重连 → 灯变绿

## 背景

S1 只证明"打开时有内容"。真实使用中内核会重启，界面必须诚实反映断连，而不是显示过期数据。

## 验收标准

1. 页面顶部显示连接状态：`已连接` / `已断开` / `重连中`。
2. 内核被杀后 ≤ 3 秒内状态变为「已断开」，并给出「重连」按钮。
3. 点重连能恢复（内核已重启的前提下），无需刷新页面。
4. 断连期间已加载的数据**标记为过期**（灰化或加角标），不假装仍是最新。
5. 一次 WebSocket 帧的 `req/res` 往返可用（哪怕只有一个 `system.echo` 方法）。

## 涉及文件

- `src/postel_studio/api/gateway.py`（新建，≤150 行）
- `src/postel_studio/api/frames.py`（新建，帧编解码纯函数）
- `src/postel_studio/api/app.py`（挂载 `/gateway`）
- `src/postel_studio/web/assets.py`（状态灯 + 重连逻辑）
- `tests/test_gateway.py`（新建）

## 测试要求

- 单测：帧编解码、`seq` 单调递增、超大帧被拒。
- 集成：真实 WebSocket 客户端连上 → 发 `system.echo` → 拿回响应 → 断开 → 断言服务端清理连接。
- 断言 `system.echo` 之外的方法返回 `UNKNOWN_METHOD`（错误码稳定）。

## 禁止事项

- 不得在断连时静默重试而不改 UI 状态。
- 不得让重连逻辑自动清空用户已输入的内容。
- 不得把连接令牌写进页面源码（从 URL 或内存读取）。
