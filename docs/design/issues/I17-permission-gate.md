# I17 · 权限闸门实测：越权必须被阻断

- **里程碑**：M3　**预计**：4h　**依赖**：I11　**优先级**：**P2 中最高**

## 背景

**如果越权拦不住，产品不该上线。** Pi 无默认 bash 沙箱；权限必须落在实际执行路径上，不能靠 Prompt 约束。

## 验收标准

1. L0（只读）Bot 尝试 `git push` 被**实际阻断**（命令未执行，返回拒绝结果）。
2. L1 Bot 尝试 push 被阻断，但允许 commit 到自己的 worktree 分支。
3. L2 Bot 允许 push 到本仓库，**不允许** push 到其他仓库。
4. 阻断必须发生在执行前（有证据：被阻断的命令无副作用）。
5. 阻断事件被记录（可供审计）。
6. 若某条路径无法阻断，必须在 UI 与文档中**明确标为不可用**，并禁止该 Bot 获得对应权限。

## 涉及文件

- `src/postel_studio/domain/permission.py`（判定）
- `src/postel_studio/agent/gate.py`（新建：执行前的裁决层）
- `tests/test_permission_gate.py`（新建，必须真实执行）

## 测试要求

- **真实执行测试**：用命令写一个哨兵文件，断言被阻断时该文件**不存在**。
- 三条权限级别各一用例。
- 审计记录断言。

## 禁止事项

- 不得用 Prompt 约束替代真实阻断。
- 不得在测试里只看返回值而不看副作用。
- 不得把无法阻断的路径静默放过。
