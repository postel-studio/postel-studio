# 09 · 切片交付标准（DoD）

> 适用：**S5 起的每一刀**。S1–S4 的退回事故事故是它的来源，不是凭空写的流程。
> 一句话：**每一刀都要能自证「验收真的验过、约束真的守得住」**——而不是「测试绿了」。

## 0. 它要挡住的三类事故

| 真实事故 | 本 DoD 的哪一条挡住它 |
|---|---|
| S1：门禁脚本改了却静默没生效；codemap 门禁 v1 只看已提交、放过未提交违例 | §3.1（目标必须被真实调用）+ §3.4（数字粘命令）；门禁自身要有反转测试 |
| S3：`.git` 目录被静默重绑到外层仓库——**测试全绿，靠审计才发现** | §1.3 边界矩阵（从数据模型枚举，不是从 happy path） |
| S3：12 条反向验证只在 `/tmp` 里手工跑过，不可复现 | §2.1（硬约束必须带固化注入） |
| S3.5：**我写的规格反向期望是错的**（U9 需两处缺陷同时存在） | §1.1（规格里的行为断言必须附可执行命令，并由作者自己跑过） |
| S4：子代理把**没跑过的推断**当实测写进代码注释、坑位文档和报告 | §3.4（自报必须贴原始输出）+ §4 第 2 条 |
| S4：一次改 226 行让 5 个模块页行号全漂；S3.5 两处坏链 | §3.1 的 `docs` 门禁（S4.5 起机械检查） |
| S4：预算一直「超标」，最后发现是分母错了 | §1.5 + [`04 §1.1`](04-task-breakdown.md) 的计量口径 |

## 1. 开工前（规格阶段）

### 1.1 规格 = 分支的第一个 commit

`docs(sX): …` 先落盘**再写代码**，同一分支、同一个 PR。规格内容：

- 验收标准（用户看到什么，不是模块具备什么）；
- 关键裁决 `D1…Dn`（字段名、错误码、DOM id、三态语义这些**契约**，写完就不许实现者自改）；
- **可执行证据**：每个「行为断言」附一条能跑的命令 + 期望输出。作者必须**自己跑过**。
  （S4 的 T33 就是这条的反例：写了「怎么复现」却没跑，跑出来跟文档相反。）

### 1.2 验收标准 → 测试映射（先写表，再写代码）

在规格里列「验收 N → 哪个测试文件/用例」，实现者照着填。没有映射的验收标准 = 没有验收。

### 1.3 边界矩阵（从数据模型/协议枚举，不是从 happy path 起）

每刀至少问一遍：这个能力碰到的实体/协议有哪些**状态**？

| 例子 | 必须覆盖的状态 |
|---|---|
| 仓库 | 普通 / 子目录 / 裸仓库 / 链接工作区 / 空仓库 / `.git` 被删 / 移动后路径失效 / 非 UTF-8 refname（U15） |
| 分支 | 当前 / 非当前 / 游离 HEAD / 上游存在或消失 / 0 分支 |
| 帧 | 参数缺失 / 类型错 / 未知方法 / 未绑定 id / 已删除实体 |
| 连接 | 就绪 / 断连 / 重连 / 端口变化 |

这条是 S3 的学费：`.git` 目录那个洞**测试全绿**，因为测试只覆盖了 happy path。

### 1.4 依赖的未决项必须先裁决

[`06-pitfalls §已知未决`](../codemap/06-pitfalls.md) 里每项都标了「到期切片」。本刀依赖的
U 项若还没裁决，**先裁决再开工**（例：S5 引入 ref 参数，必须先定 U15「ref 名怎么过边界」）。

### 1.5 `src/` 预算估计

开工前写下预计的 `src/` 行数与文件数（上限见 [`04 §1`](04-task-breakdown.md)）。
预计超了就先拆——**而不是做完再解释为什么超**。

## 2. 实现中

### 2.1 每条新的硬约束配一条反向注入

新增安全 / 数据 / 协议类约束时，往 `tests/test_reverse_checks.py` 加一条：
把实现改坏 → 断言**指定**的那条测试变红。只写「有测试」不算——S3 那条
`assert GIT_TIMEOUT_SECONDS > 0` 把超时改成 0 也还是绿的。

### 2.2 错误码只用 07 §1.3 表内的

新增码 = 破坏契约。确实需要时，同一个 PR 里改 `07-api-contract.md` 的表 + `errors` 映射，
并在 PR 体里单独标出来。

### 2.3 不许静默扩边界

`conftest.py`、CI 配置、依赖（`pyproject.toml` / `uv.lock`）、`tools/acceptance/` 之外的
新目录，变更必须在 PR 体里单独一行说明；不改也要说「没动」。

### 2.4 小 commit，写清意图

conventional commits，**英文**描述（S6.6 起；历史 commit 保持中文，不改写历史）。一个逻辑改动一个 commit（分层、接线、前端、测试、文档各算一块）。
被要求返工时**追加 commit**，不要 rebase 掉历史——审查要看得到返工过程。

## 3. 交付前（门禁）

### 3.1 `bash scripts/check.sh all` 全绿

含 lint / format / types / test / **docs** / **layers** / codemap / secrets。
`build` 单独跑一次（慢，不在 `all` 里）。

### 3.2 改了前端 → 跑**全部** `tools/acceptance/*.mjs`

不只跑本刀新写的那份：前端是被多刀共用的，S4 改 `assets.py` 时必须重跑 S3 的脚本。
缺 Chrome / puppeteer 时脚本会 `SKIP` 并 exit 0 —— **跳过要在 PR 体里写明**，不能当成通过。

### 3.3 独立审计（审查者的活，但 PR 体要能看出做过）

审查者用自己的脚本/命令复核，不复用实现者的测试。至少要有一项**实现者没写过**的检查
（S4 的三件套：接口边界、静态契约、文档链接；S3 是 AST 级 `shell=True` 扫描）。

### 3.4 自报必须贴**命令的原始输出尾部**

不许写「全部通过」。要贴：

```text
196 passed in 29.58s
Total coverage: 82.36%
```

以及验收脚本的 `CHECK ✓/✗` 计数。**数字一律粘自命令**，不许凭记忆（S3 曾把
`+4139/−61/32 files` 报成 `+2600/−60/26`）。

## 4. PR 体必填（**英文**，S6.6 起；模板见 `.github/PULL_REQUEST_TEMPLATE.md`）

| 项 | 要求 |
|---|---|
| 用户路径 | 一句话：用户能看到什么 |
| 验收 → 测试映射 | 表格，逐条对应 |
| 契约摘要 | 新增/变更的字段、错误码、DOM id |
| 证据 | `check.sh` 尾部、覆盖率、验收脚本计数、独立审计结果 |
| 预算 | `src/` 文件数/行数 + 全量 `git diff --stat`（口径见 04 §1.1） |
| 未做 / 未验 | **分开写**；跳过与没做都要说明原因 |
| 未决项变化 | 新增 U 项、结案的 U 项 |
| 数字来源 | 说明所有数字粘自哪个命令 |

## 5. 本 DoD **不**要求什么（避免伪精确）

- 不要求覆盖率数字好看：60% 是下限，靠 review 把关，不靠追指标；
- 不要求文档「内容」正确：门禁只查链接/锚点/行号/行数表，文字质量靠 review（06 U8）；
- 不要求每个边界都**修**：可以记 U，但必须给「到期切片 + 不解决的后果」；
- 不要求单测覆盖浏览器 DOM：那部分只由 `tools/acceptance/` 证明（06 T9），**不假装覆盖了**。
