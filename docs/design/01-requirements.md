## 1. 一句话定位

**一个以仓库变更为中心、Bot 常驻仓库、Agent 可插拔、本地执行优先、Git 平台无关的 Agent 工作台。**

不是又一个 AI IDE，也不是又一个 Git 客户端，而是 **Agent 时代的 Git 工作台**：人在仓库全景里派活、看 diff、做验收；Bot 在仓库里常驻、认领工作、产出候选变更。

## 2. 三条不可退让的差异化

1. **仓库是第一视图**，不是编辑器的附属侧栏。
2. **Bot 常驻仓库、Agent 可插拔**，不绑定单一模型或厂商。
3. **本地执行优先 + 可选沙箱**，Git 平台无关。

守住这三条，产品讲的是「Agent 时代的 Git 工作台」，而不是「又一个 AI IDE」。

## 4. 权限模型（修正后）

原文档的 5 级是线性排序，但**「合并」与「跨仓库 PR」不是同一维度**：前者是对自己仓库的写，后者是向外部发布。

| 级别 | 允许 | 默认 | 第一版实现 |
|---|---|---|---|
| L0 只读 | 读文件、跑只读命令 | — | 是 |
| L1 改工作区 | 在自己的 worktree 里改、commit 到 Bot 分支 | 鼓励 | 是 |
| L2 推分支 | push 到**本仓库**的 Bot 分支 | 需人启用 | 是 |
| L2+ 本仓库 PR | 开 PR 到本仓库 | 需人启用 | 是 |
| L3 跨仓库 PR | fork + 提 PR 到上游他仓库 | **默认关闭**，每次手工批准 | 否（M4 后） |
| L4 合并 | 合并到主分支 | **永不** | 否 |

> 「默认」列说的是**产品倾向**，不是代码里的默认值。新建 Bot 的默认级别是 **L1**
> （[05 §2.2](05-security.md)：可改工作区、不可推送），S8 起由 `bot.create` 落库。
> 本表 L0 行原先写着「新 Bot 默认」，与 05 §2.2 / 06 §2.2 / 建表 DDL / S8 验收四处矛盾，
> S8 按那四处改正（裁决记录见 [S8 D2](issues/S8-create-bot.md)）。

## 5. 记忆空间四层

| 层 | 内容 | 更新时机 | 是否进仓库 |
|---|---|---|---|
| ① 宪法层 | 职责、权限、禁止事项（`charter.md`） | 人手工编辑，极少变 | 否；可由人批准后**只读投影**为 `.postel/bot.md` |
| ② 规范层 | `AGENTS.md` / `README.md` 的分层投影 | 随仓库变化 | **不复制**，每次任务启动时从仓库**实时读取** |
| ③ 经验层 | 见过的坑、有效的做法 | 每次任务后沉淀 | 否；会膨胀，需压缩机制 |
| ④ 短期层 | 当前任务上下文与日志 | 单任务内 | 否；任务结束可清 |

**冲突规则**：仓库层（②）永远优先；Bot 级（①）只能**加严**不能放宽；冲突时在注入阶段**阻断并报错**，不静默取一个。

## 6. 连接能力

### 6.1 事实基线（2026-11-26 实测）

| Agent | ACP 支持 | 启动方式 | 本机 |
|---|---|---|---|
| OpenCode | 原生 | `opencode acp [--cwd <dir>]` | 已装 1.19.6，握手通过 |
| DeepSeek Harness | 原生（`@deepseek-ai/dsh-acp`） | `dsh --profile acp`（`acp` 是 profile 名，非子命令） | 已装，`acp` profile 未创建 |
| Pi (`@earendil-works/pi-coding-agent`) | **无原生 ACP** | SDK 嵌入（`createAgentSession`） | 已确认可嵌入 |

### 6.2 从 T3 学到的原则

- **编排与客户端只读能力，不读驱动种类。**
- **能力旗标只能报真实的**；报了点却跑不通就是 bug。
- 权限模式只提供 Agent **原生强制**的那些；**不要用自己的审批去伪造 Agent 缺失的模式**——你的检查比 Agent 自身的强制更弱。
- **不要**在通用适配器里写单个 Agent 的特例；确有特例只做成薄「风味」覆盖。

### 6.3 两条通道，一个内核接口

| 通道 | 对端 | 协议 | 维护方 |
|---|---|---|---|
| ACP 通用通道 | OpenCode / DSH / 任意 ACP Agent | ACP over stdio | 我们（内核侧） |
| Node PI 运行时 | pi-coding-agent SDK 嵌入 | 私有 socket | 我们（Node 侧） |

内核**不需要知道**对面是 ACP 还是 PI。两条通道对内核暴露同一种「Bot 运行时」接口。

### 6.4 凭据原则

**凭据不进 Agent 环境变量**，由代理持有，按 Bot 权限放行。理由：L1 的 Bot 就不该看见能 push 的令牌。

### 6.5 ACP 与 Git 的边界

ACP 只报告工具调用与文件编辑，**没有「我要提交了」这一语义**。因此：

- Agent 会话结束后，编排层必须检查：是否私自切了分支、是否有多余 commit、是否有越界写；
- 最终 commit 由**我们**在受控分支上做唯一一次，不能指望 Agent 收尾。

## 7. MVP 边界

**做**：

- GitHub 单平台；
- 本地 clone + 完整仓库视图（代码树、分支、diff）；
- 仓库 → Bot 两级结构，Bot 有身份、记忆、worktree、工作日志；
- 通用 ACP 通道（首个对端 OpenCode）+ 1 个 Node PI 运行时；
- worktree 隔离 + L0~L2+ 权限 + 变更收件箱；
- `AGENTS.md` 分层注入与可见性。

**不做**：

- 完整 Issue/PR 管理；
- 自研模型或 Agent 内核；
- 多平台全覆盖；
- 远程沙箱完整实现（只留接口）；
- 跨仓库 PR（L3）与合并（L4）。

## 9. 已知风险

| 风险 | 说明 |
|---|---|
| 赛道拥挤 | Cursor / Kiro / CNB 都在往「Agent + 仓库」靠，必须靠三条差异化守住 |
| **核心假设未经证伪** | 「Bot 常驻仓库、产 diff 而非聊天，人更愿意用」只能靠真实用户验证 |
| 适配器工程量 | 「接入所有 Agent」起步容易、跑稳很难；生命周期、上下文协议、权限审批是重活 |
| Pi 生态迁移期 | 包已从 `@mariozechner` 迁到 `@earendil-works`，API 面可能仍有变动，必须钉版本 |
| Pi 无默认 bash 沙箱 | 权限闸门必须落在 `tool_call` 阻断上，不能靠 Prompt 约束 |
