# 04 · 任务拆解

> 状态：重拆 v2 · 2026-11-26
> 上游：[docs/](README.md)
> **本版目标：让每次 AI 生成都是小 diff、可审查、可回滚。**
> v1 见 git 历史（按模块横切，已废弃）。

---

## 0. 与 v1 的差别（为什么重拆）

v1 的切片是**按模块**切的：`ACP 拉起` → `ACP 会话` → `持久化`。结果每个 Issue 做完**演示不了任何东西**，
且模块之间的接口在拆解时并不存在，只能靠猜。

v2 改成**按用户路径**切：每一刀都对应「人打开界面能看到的一个变化」。
代价是同一个模块会被多次触碰（如 worktree 在 M2 出现 3 次），但换来三个好处：

1. **每刀都能演示**——验收标准写的是「用户看到什么」，不是「模块具备什么能力」。
2. **每刀的 diff 天然小**——只为一个可见结果服务，不会顺手把整层写完。
3. **可回滚**——任一 PR 回滚，最多损失一个可见能力，不会留下半套架构。

## 1. 小 diff 的硬性预算

| 项 | 上限 | 超了怎么办 |
|---|---|---|
| **`src/` 变更行数** | **≤ 400 行**（新增+删除） | 继续拆 |
| **`src/` 触及文件数** | **≤ 12 个** | 继续拆 |
| 单个 Issue 工作量 | **≤ 4 小时** | 继续拆 |
| 单个 PR 新增公开接口 | **≤ 3 个方法** | 拆成「先能用假的，再换真的」 |

> 这是**写作时的约束**，不是事后检查。如果拆到发现某个 Issue 必然超预算，说明它不是一个切片，是两件。
>
> 每一刀交付前还要过一份清单：[09-slice-dod.md](09-slice-dod.md)（规格、边界矩阵、反向注入、
> PR 体必填项、独立审计）。预算管**大小**，DoD 管**质量**，两者不互相替代。

### 1.1 计量口径：行数与文件数**只统计 `src/`**

**裁决（S4 收尾，2026-11-26）**：`tests/`、`tools/acceptance/`、`docs/` **不计入 400 行 / 12 文件上限**。

| 目录 | 计入上限 | 理由 |
|---|---|---|
| `src/` | ✅ | 产品体积与长期维护面就在这里 |
| `tests/` | ❌ | 验收成本，不是产品体积；每多一条验收标准就该多一条测试 |
| `tools/acceptance/` | ❌ | 同上（真实浏览器验收，不进 CI、不进依赖） |
| `docs/`（含 codemap） | ❌ | 设计/代码地图是维护资产；门禁已经强制「改 `src/` 必须同步 codemap」 |

**为什么改**：S1/S2/S3/S3.5/S4 五刀全部「超标」，但 S4 拆开看是
`src/` **6 文件 / +397 行**（**在限内**）、其余 19 文件是测试 633 行 + 验收脚本 480 行 + 文档 599 行。
上限本身没错，是**分母**错了：按旧口径，守规矩的唯一办法是删测试或砍验收项——那只是把超支藏起来，
而不是变小。`src/` 的行数上限仍然是硬约束，超了照样继续拆。

**新增约束**（把「不计入」换成可检查的）：不计入上限 ≠ 不设防——测试与文档靠
DoD 与门禁守：**每条验收标准至少一条真测试**、**改 `src/` 必须同步 `docs/codemap/`**（已有门禁）。

> 历史 Issue 文档里的「≤400 行 / ≤12 文件」交付检查项按**当时**口径书写，不回改；
> 从 S4 起的切片按本节口径结算。

## 5. 优先级

- **P0**：S1~S5、S7~S11 —— 端到端最小闭环，缺一刀就演示不了「派活 → 出 diff」。
- **P1**：S6、S12~S14 —— 让闭环**可被人验收**（有收件箱、能批准）。
- **P2**：S15~S20 —— 可上线性。其中 **S16（越权拦截）优先级高于其他 P2**：拦不住就不该上线。

## 6. 全局禁止事项（适用所有 Issue）

- **不得**把 `.env` 或凭据写入代码、测试、日志、提交。
- **不得**在提交前跳过 `bash scripts/check.sh`。
- **不得**在通用接入层写单个 Agent 的特例分支（如 `if agent == "opencode"`）。
- **不得**把能力旗标硬编码；能力必须来自运行时响应。
- **不得**让 Bot 拥有合并（L4）能力。
- **不得**在未实测前，在文档或 UI 中宣称某能力「已支持」。
- **不得**修改 `~/.dsh/profiles/` 或用户现有环境配置。
- **不得**用 mock 替代 git / ACP 的真实行为作为唯一测试手段。
- **不得**在单个 PR 里同时改动两个用户路径（超预算，见 §1）。
- **不得**直推 `main`；一律特性分支 + PR。
