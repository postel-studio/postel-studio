## 2. 拆解原则

1. **垂直切片**：UI → 接口 → 数据 → 测试，一次打通一条用户路径。
2. **禁止横切**：不得「先写所有模型、再写所有接口、再写所有页面」。
3. **每个任务 1~4 小时可完成**，超过就继续拆。
4. **每个任务必须能独立验收**：有明确的验收标准与可执行的验证命令。
5. **先打通端到端最小闭环，再补功能**：M1 的切片全部为了让 M2 最短路径成立。

## 5. 优先级

**P0（M1 全部 + M2 的 I07~I12）**：端到端最小闭环。任何 P0 未完成前不开始 P1。

**P1（M2 的 I13~I15）**：让闭环可被人验收。

**P2（M3）**：可上线性。其中 **I17（权限闸门实测）优先级高于其他 P2**——如果越权拦不住，产品不该上线。

## 6. 全局禁止事项（适用于所有 Issue）

- **不得**把 `.env` 或任何凭据写入代码、测试、日志、提交。
- **不得**在提交前跳过密钥扫描（`git diff --cached | grep -E 'ghp_|pypi-'`）。
- **不得**在通用接入层写单个 Agent 的特例分支（如 `if agent == "opencode"`）。
- **不得**把能力旗标硬编码在配置里；能力必须来自运行时响应。
- **不得**让 Bot 拥有合并（L4）能力。
- **不得**在未通过实测前，在文档或 UI 中宣称某能力「已支持」。
- **不得**修改 `~/.dsh/profiles/` 或用户现有环境配置文件。
- **不得**用 mock 替代 git / ACP 的真实行为作为唯一测试手段（真实行为必须有至少一条集成测试）。
