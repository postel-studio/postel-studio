## 0. 威胁模型

产品是**本地优先的单机桌面工具**，不是多租户服务。威胁模型必须如实声明，否则会防错方向。

| 资产 | 价值 | 可能被谁拿走 |
|---|---|---|
| Git 令牌 / AI Provider Key | 高（可推代码、可花钱） | Agent 越权读取、日志泄漏、误提交 |
| 用户源码 | 高（商业机密） | 越界写入/上传、prompt 外泄 |
| Bot 记忆（含经验层） | 中（可能含片段源码） | 跨仓库共享、日志 |

**在威胁模型之内**（必须防）：

1. Agent 越权访问文件系统（worktree 之外）。
2. Agent 越权执行 git 写操作（push / 切分支 / 改主仓库）。
3. 凭据经日志、错误消息、UI、提交历史泄漏。
4. 跨 Bot / 跨仓库的隐式信息共享（记忆串味）。
5. 恶意或投毒的 Agent Registry 条目。

**明确不在威胁模型之内**（要做也不要声称做到了）：

- 拥有本机同一用户 shell 权限的攻击者——**同用户下的隔离不是安全边界**，OS 层面无法防御。
- 供应链级别的恶意（除非我们引入来源校验，见 §5）。
- 物理接触、内存取证、内核级恶意软件。

> 一句话：**我们防的是「Agent 跑偏」和「凭据不小心外泄」，不是「主机被攻陷」。** 文档与 UI 的任何措辞都不得暗示后者。

## 1. 认证（AuthN）

### 1.1 内核 ↔ 客户端

本地内核不暴露公网。三条硬规则：

1. **绑定 `127.0.0.1`**，绝不 `0.0.0.0`。若用户显式要求远程访问，必须走独立的隧道模块（不在 MVP），且不得复用本地端口。
2. **每次启动生成一次性连接令牌**（32 字节随机），写入独立文件 `~/.postel/token`（权限 `600`，**不写进 `server.json`**）；`server.json` 只放 `tokenFingerprint`（sha256，供判断文件归属）。客户端必须携带 `Authorization: Bearer <token>` 才能建立 WebSocket。
3. **令牌随进程退出失效**，不落盘到其他位置，不写入日志。

- 令牌比较必须用**常量时间**比较（`hmac.compare_digest`），防时序侧信道。
- 令牌**不做**加盐哈希存储——它生命周期只有一次进程，落盘即明文但权限 600，这是**有意的取舍**：哈希会增加启动时的额外状态而无实际收益。
- **禁止**做「记住我」、长期 token、cookie 持久化。

#### 1.1.1 浏览器侧的握手凭证（S2 裁决 D1）

第 2 条「客户端必须携带 `Authorization: Bearer <token>`」在**浏览器**侧物理上做不到：
`new WebSocket()` 只接受 URL 与 subprotocol，无法设置自定义请求头。

两条看似可行的替代路都触碰硬约束，故均否决：

| 替代路 | 为何否决 |
|---|---|
| 令牌放进 URL（`?token=`） | 违反 §4.1「凭据不进日志」——URL 会进访问日志、`ps`、浏览器历史 |
| 渲染页面时把令牌注入 `<script>` | 直接违反「令牌不得进页面源码」 |

**采用的第三条路：把「握手认证」与「长期凭据」拆开。**

1. 内核另生成 **handshake ticket**（32 字节随机、仅存内存），随根页面 `/` 下发到
   `<meta name="postel-handshake">`；根页面本身不含任何长期凭据。
2. ticket **有效期 60 秒、单次使用**：验证后立即从内存删除；无论是否使用，60 秒后作废。
3. 浏览器把它放进 `/gateway?ticket=…` **用一次**；此后该串已作废，泄漏面只剩一个无效随机值。
4. ticket **不是** `token`：它不能用于任何 HTTP 请求、不能换第二个连接、永不落盘。
5. `~/.postel/token`（第 2 条的长期令牌）约束**完全不变**，留待将来的 CLI / 脚本客户端使用。

**为什么这不算降低标准**：长期凭据仍未进入页面、未进入 URL、未进入日志；被放进去的只是一个
60 秒内、仅一次有效的随机值，与一次性 CSRF token 同性质。**代价**：ticket 有效期内的同机进程
若抢先取走它，可夺得一次连接——但这需要「同用户 shell 权限」，而 §0 已把该情形排除在威胁模型之外。
若将来产品要给浏览器做远程访问，此机制**必须重做**。

**禁止**：把 ticket 有效期调长、让它可重用、或把它写进 `server.json`。`server.json` 里的
`wsPath` 是稳定的路径前缀（状态根哈希），**不是凭据**；内核日志里 WS 查询串一律打成
`?<REDACTED>`，否则 ticket 会随 uvicorn 的 WS 日志进日志。

### 1.2 客户端 ↔ Git 平台

- 只从 `.env` 或系统凭据管理器读取，**不写入代码、不写入数据库**。
- 注入方式：子进程环境变量仅对**需要它的那一个子进程**生效，用完即弃。
- **禁止**把令牌写进 URL（`https://token@github.com/...`）——它会出现在 `ps`、日志、`.git/config` 里。

### 1.3 首次使用

无登录界面。产品不持有账户体系；对 Git 平台的认证由用户已有的凭据承担。

## 2. 权限（AuthZ）

术语与 [01-requirements.md](01-requirements.md) §4 的 L0~L4 一致。本节只补充**执行层面**的约束。

### 2.1 判定发生在执行前

```
请求 → permission.check（纯函数，无 IO） → 允许 / 拒绝
                                    ↓ 允许
                              实际执行（exec / git）
```

**硬约束**：

1. 判定必须发生在**执行之前**，且判定与执行之间不存在可绕过的第二路径。
2. 拒绝时**命令本身不得被执行**（不是"执行了再报错"）。验收方式：会写哨兵文件的命令，被拒时哨兵文件不存在（见 I17）。
3. 判定**不得**依赖 Agent 自报（Agent 的沙箱/审批比我们弱或不可信）。
4. 判定**不得**读取 Agent 类型做分支，只读 Bot 的权限级别。

### 2.2 默认值

| 场景 | 默认 |
|---|---|
| 新建 Bot | **L1**（可改工作区，不可推送） |
| 未知/缺省权限 | L0（只读）——**失败即收紧，不失败即放开** |
| L3 跨仓库 PR | 关闭，且每次需人工确认 |
| L4 合并 | **产品不提供** |

### 2.3 不可协商的禁令

- Bot **永不**能合并到主分支。
- Bot **永不**能改写自己的权限级别。
- Bot **永不**能编辑 `charter.md` 的权限字段（只有人能改）。
- 权限**降级立即生效**；升级可需要重启（降低可用性可接受，提升安全性必须即时）。

## 3. 输入校验

原则：**边界处全部校验，内部信任**。校验点只有三处——协议帧、文件系统路径、子进程参数。

### 3.1 协议帧

| 检查 | 规则 | 失败 |
|---|---|---|
| 帧大小 | ≤ 1 MiB | 关闭连接并记录 |
| JSON 合法性 | 必须能解析为对象 | 忽略并计数（不崩溃） |
| `type` | 必须是 `req` / `res` / `evt` | 忽略 |
| `method` | 必须在白名单内 | `UNKNOWN_METHOD` |
| `id` | 字符串，长度 ≤ 128 | 拒绝 |
| 字段类型 | 按方法签名逐字段校验 | `INVALID_PARAMS` |

**禁止**信任任何来自帧的路径、命令、分支名。

### 3.2 路径

- 所有用户输入的路径必须 `resolve()`（消除 `..`、符号链接）后，**断言其在允许根之内**。
- 允许根：绑定的仓库路径、`~/.postel/worktrees/`、`~/.postel/bots/`。
- 断言失败：`PATH_OUTSIDE_ROOT`，**不回显解析后的绝对路径给客户端**（防信息泄漏）。
- 符号链接：`resolve()` 后判定，**不信任**链路上的 `..`。

### 3.3 子进程参数

- ACP 命令与参数必须是**字面数组**，直接 `exec`（或 `subprocess` 列表形式），**不经 shell**。
- **禁止** `shell=True`、`os.system`、字符串拼接命令、展开 `~` / `$VAR` / 通配符。
- 分支名必须白名单校验：`^[a-z0-9][a-z0-9._/-]{0,200}$`，且不得以 `-` 开头（防被当选项），不得含 `..`（防路径穿越）。
- Bot 名同样白名单：`^[a-z][a-z0-9-]{0,31}$`。

### 3.4 注入防护

- **AGENTS.md / README 注入的内容不得被执行**，只作为文本进入 prompt。
- 注入内容必须标注来源（文件路径 + 层级），并告知模型这是**数据不是指令**。
- 注入长度必须有上限，超限截断并标记（不静默丢弃）。

## 4. 密钥管理

### 4.1 存储

| 凭据 | 位置 | 权限 |
|---|---|---|
| Git / PyPI token | `.env`（已被 `.gitignore`） | 由用户机器保证 |
| AI Provider key | `.env` 或系统凭据管理器 | 同上 |
| 内核连接令牌 | `~/.postel/token`（独立文件） | **`0600`，进程退出即删除**；`server.json` 只放 `tokenFingerprint`（sha256） |
| Bot 记忆中的内容 | `~/.postel/bots/` | `0700` 目录 |

- **凭据绝不进入**：SQLite、日志、UI 帧、错误消息、Git 提交历史、Agent 的环境变量（见 §4.3）。
- `.env` 权限检查：启动时若发现 `.env` 组/其他可读，`doctor` 必须报警。

### 4.2 脱敏

- 日志：正则 `(ghp_[A-Za-z0-9]{30,}|pypi-[A-Za-z0-9_-]{40,}|sk-[A-Za-z0-9]{20,}|AKIA[0-9A-Z]{16})` 替换为 `…<REDACTED>`；同时做**长度泛化**（长度也隐藏，防暴力还原）。
- 错误响应：**不回显**任何输入值，只回显错误码与字段名。
- UI：显示 token 类字段时一律 `前6位…`，不显示完整值。

### 4.3 代理层（凭据不入 Agent 环境）

**硬约束**：Agent 子进程的环境变量中**不得包含**可用于 push 的令牌。

- 需要远端操作时，由**内核**发起（Bot 只产出本地分支），而非把令牌交给 Agent。
- 若将来必须让 Agent 触网，走代理进程：Agent 连代理，代理按 Bot 权限注入凭据。**代理本身不得记录凭据**。

### 4.4 轮换

- 令牌泄露时，`.env` 替换后**无需重启即可生效**（每次取用时读取，不缓存）。
- `doctor` 提供「凭据是否仍有效」的只读探测。

## 5. 供应链（引用的第三方）

| 引入物 | 风险 | 措施 |
|---|---|---|
| ACP Agent（Registry） | 第三方代码，可选恶意 | **安装前必须人确认**；UI 显示来源与许可证；记录版本 |
| Pi SDK | 上游 API 可能变 | **版本钉死**；升级走显式 PR |
| MCP Server | 可获得 Agent 的上下文 | 默认不自动连接到未知 server；显示连接清单 |

**禁止**：全自动从 Registry 安装任意 Agent 且不显示来源。**不得**声称「已验证安全性」——我们只做披露与固定版本。

## 6. 隐私

- **不收集遥测**。任何统计上报必须显式开启，且默认关闭。
- **不上传源码**。Agent 调用外部 API 时，prompt 中含有的源码片段随请求外发——这一点**必须在 UI 明确告知**，因为用户有权知道代码会离开本机。
- **记忆不进仓库**（D1），且跨仓库不共享。
- 日志默认本地，保留期由用户控制；`doctor` 提供一键清理。
- 卸载时不删除 `~/.postel`，但提供显式清理命令并**二次确认**。

## 7. 验收清单（每个 PR 都要过）

- [ ] 新增路径处理是否经 `resolve()` 并在允许根内？
- [ ] 新增子进程调用是否**列表形式、无 shell**？
- [ ] 新增日志是否可能打印凭据或绝对敏感路径？
- [ ] 新增权限判定是否在执行**之前**？
- [ ] 是否新增了把凭据交给 Agent 的路径？（应为禁止）
- [ ] 是否引入了新的第三方包，版本是否钉死？
- [ ] UI 新增文案是否夸大安全保证（如「已加密」「绝对安全」）？

> 最后一条同样重要：**不夸大的安全声明是安全的一部分。**
